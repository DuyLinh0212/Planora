# ENVIRONMENT CONFIGURATION

`.env.example` ở repository root là template duy nhất cho local. Không dùng lại các template SQL Server/ZaloPay cũ.

## Local development

1. Copy `.env.example` thành `.env`.
2. Start PostgreSQL: `docker compose up -d postgres`.
3. Thay các giá trị `CHANGE_ME_*` và thêm credential provider nếu cần.
4. Apply EF migrations:

```powershell
dotnet tool restore
dotnet tool run dotnet-ef database update `
  --project backend/src/Planora.Infrastructure `
  --startup-project backend/src/Planora.Api
```

The local database is PostgreSQL. SQL Server is only an optional legacy source for the isolated one-time migration utility in `backend/tools/Planora.DataMigration`.

## Backend runtime variables

ASP.NET Core maps `__` to nested configuration keys. Secrets belong in .NET user-secrets locally or Render Environment secrets in production.

| Group | Variables | Secret? |
|---|---|:---:|
| Runtime | `ASPNETCORE_ENVIRONMENT`, `ASPNETCORE_URLS` | No |
| Database | `ConnectionStrings__DefaultConnection` | Yes |
| JWT | `Jwt__Issuer`, `Jwt__Audience`, `Jwt__Secret`, token lifetimes | Secret |
| External auth | `Authentication__Google__*`, `Authentication__Facebook__*` | Client secret only |
| Gmail/email | `PasswordReset__*`, `TaskEmailNotifications__*`, `GmailIntegration__*` | Yes, except public ClientId |
| Cloudinary | `Cloudinary__CloudName`, `Cloudinary__ApiKey`, `Cloudinary__ApiSecret` | ApiKey/ApiSecret |
| Storage | `Storage__MaxFileSizeMb` | No |
| MoMo | `Payment__Momo__PartnerCode`, `AccessKey`, `SecretKey`, `Endpoint`, `ReturnUrl`, `IpnUrl`, `RequestType` | Credentials/URLs as appropriate |
| Bank transfer | `Payment__BankTransfer__BankName`, `AccountName`, `AccountNumber`, `Branch`, `PaymentReferencePrefix`, `SePayWebhookApiKey` | Account/webhook key |
| Database startup | `Database__ApplyMigrationsOnStartup` | No |
| CORS | `Cors__AllowedOrigins__0`, `Cors__AllowedOrigins__1`, ... | No |

Production payment activation is automatic. MoMo IPN and SePay webhook are verified server-side; do not activate a subscription from a browser redirect. Callback retries are idempotent.

## Render

Use `render.yaml` to create the Docker web service. Fill every `sync: false` variable in Render. Keep `Database__ApplyMigrationsOnStartup=true` for the single production instance during deploy, and use a public HTTPS API origin for:

```text
Payment__Momo__ReturnUrl=https://<user-web-domain>/billing
Payment__Momo__IpnUrl=https://<api-domain>/api/payments/momo/ipn
https://<api-domain>/api/payments/bank-transfer/sepay/ipn
```

The Neon connection string must use SSL in production. Never paste it into source, frontend environment files, Vercel variables, screenshots or issue comments.

## Frontend public configuration

Angular production files are generated by `tools/ci/write-frontend-environment.mjs` during CD from these GitHub Environment variables:

- `PLANORA_API_URL`: public HTTPS API origin without trailing slash.
- `PLANORA_GOOGLE_CLIENT_ID`: public browser OAuth client id for User Web.

Only public origins and browser client IDs may be embedded in frontend bundles. MoMo, SePay, Neon, Cloudinary, SMTP, Gmail token-encryption and JWT secrets must remain backend-only.

## GitHub Actions Environment

The complete production secret list and reviewer/branch-protection policy is maintained in `docs/docs/CI_CD.md`. Do not put production secrets in repository variables when an Environment secret is appropriate.

## Secret hygiene

- Keep `docs/KeyDB.md`, `docs/KeyCloudinary.md`, `.env`, client-secret JSON, certificates and Android keystores local; they are ignored and CI rejects tracked copies.
- Rotate any credential that has ever appeared in a commit, terminal transcript or public issue.
- Use `git rm --cached <path>` to untrack a secret without deleting the local file.
